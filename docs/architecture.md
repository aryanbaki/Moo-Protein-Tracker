# Architecture

## Stack
Expo SDK 58 (58.0.23) with React Native 0.88.1, React 19.3.0, strict TypeScript,
and Expo Router. npm is the only
package manager. The lockfile records the actual resolved dependency versions.
The foundation uses stable SDK 58, initialized from Expo's official default template.

## Folder structure
- src/app/_layout.tsx: shared navigation, status bar, and safe-area provider.
- src/app/index.tsx: the home route with the Moo title and tagline.
- src/theme/index.ts: reusable color, spacing, and typography values.
- docs/: product scope, architecture, task state, and verification.
- .github/workflows/checks.yml: cloud TypeScript, lint, and Expo Doctor checks.
- app.json: app display/configuration; deliberately no account/signing identifiers.

Keep routes thin as features grow. Introduce src/components for shared UI,
src/features for logging/goals/history logic, and src/storage for persistence
only when those features are implemented. Native projects are generated by
Expo/EAS rather than checked in.

## Planned local storage
Use expo-sqlite for structured, device-local persistence once logging is built.
It is not installed or implemented in this foundation.
A storage module will own versioned migrations and typed read/write methods;
screens must not issue SQL directly.

Plan for entries with a stable ID, nutrient type (protein or creatine), amount in
grams, optional label, event timestamp, and local calendar day. Store user-set
goals separately. Decide and test timezone/day-boundary behavior before shipping
history. Preserve an entry's recorded day when timezone changes. Derive daily
totals and cow progress from stored entries and explicit goals; handle unset or
zero goals without division errors.

Validate positive finite amounts and goal inputs. Migration, edit/delete, date
boundary, and progress calculation tests are required when implementing logic.
No data persistence or cloud synchronization exists yet.

## Cloud workflow
Codex and Claude Code share AGENTS.md. A cloud coding environment can install
dependencies and run checks. EAS builds and signs native binaries in the cloud
after account linking and Apple signing are configured in a later step.
Preview/production binaries bundle JavaScript and do not need a laptop or Metro
server to remain running. Interactive Metro development still needs an active
development environment.
